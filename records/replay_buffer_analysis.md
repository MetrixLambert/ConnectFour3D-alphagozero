# Replay buffer 阶段分布检查

检查对象：iteration 620 完整 checkpoint
`saved_models/checkpoints/stage2_sim200_temp08_lr1e4_from590_iter_000620.pt`，并与
iteration 340 的完整 checkpoint 对照。每条 state 的非零棋子数等于该样本的 ply，因而
不需要额外手数 metadata 就能精确划分对局阶段。

## 原始 buffer 分布

| checkpoint | 样本数 | ply 均值/中位数 | 0–9 | 10–19 | 20–29 | 30+ |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| iteration 340 | 31,966 | 5.69 / 5 | 83.1% | 15.1% | 1.4% | 0.3% |
| iteration 620 | 50,000 | 9.75 / 7 | 61.2% | 24.0% | 11.4% | 3.4% |

iteration 620 的原始 buffer 仍以前 10 手为多数，这是因为每局都产生前期样本，只有未提前
结束的长局才产生后期样本；但相较 iteration 340，中后期覆盖已经大幅改善，不能认为新
模型的 buffer 比旧模型更偏前期。

## 当前分层采样下的实际 batch 分布

iteration 620 的历史 40,000 条中，0–9/10–19/20–29/30+ 占比为
66.5%/22.0%/8.9%/2.7%；最新 10,000 条为 40.2%/32.3%/21.3%/6.2%。训练每个 batch
从两部分各取 50%，所以有效训练占比约为 53.4%/27.1%/15.1%/4.4%。近期数据明显包含
更多长局，现有 recent/history 分层采样已经间接提高后期权重，但没有显式保证阶段平衡。

所有样本的 value 绝对值均为 1，说明所覆盖自博弈没有和棋。iteration 620 的平均 policy
熵在 0–9 手约为 1.287，10–19 手约为 1.684，20–29 手约为 1.809，30+ 约为 1.785；搜索
在前期明显更集中，在中后期更不确定。这与人工体验中的“前期稳定、后期容易出错”一致。

后续若专门改善残局，优先方案是在保留 recent/history 配额的基础上再做 ply 分层采样，
而不是简单继续扩大 buffer：例如将 batch 按 0–9、10–19、20+ 分配固定配额，同时在各层
内部继续保留近期/历史样本。实施前应先评估 iteration 620 的现状并建立残局测试集，避免
过度提升后期权重而损伤开局能力。
